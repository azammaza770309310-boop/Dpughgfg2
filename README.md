# CrowdCloud (نسخة المحادثة) — تشغيل المشروع

نسخة مطوّرة من المشروع الأساسي بإضافتين: خانة «طلبك أو استفسارك» عند إصدار
التذكرة، ومحادثة خاصة بين الطالب والموظف داخل كل تذكرة. كل ما عدا ذلك كما
في النسخة الأساسية.

## ما الجديد في هذه النسخة

1. **خانة الطلب/الاستفسار:** عند إصدار التذكرة يكتب الطالب طلبه أو استفساره،
   فيُخزَّن مع التذكرة ويظهر للطالب في صفحة تذكرته وللموظف في لوحة الموظف
   (ولا يظهر في لوحة الطابور العامة — البقية لا تراه).
2. **محادثة خاصة طالب ↔ موظف:** زر «محادثة الموظف» في صفحة التذكرة يفتح
   محادثة خاصة بهذه التذكرة فقط:
   - الطالب **لا يستطيع إرسال أي رسالة أو صورة أو ملف** إلا عندما يحين
     دوره (أي عندما تصبح حالة التذكرة «قيد الخدمة»). قبل ذلك المحادثة
     للقراءة فقط، والرفض مفروض من الخادم (403) وليس من الواجهة فقط.
   - المحادثة تعمل أثناء الانتظار (الموظف يستطيع المراسلة) وأثناء الخدمة
     (كلا الطرفين)، وتُغلق نهائيًا عند إكمال التذكرة أو إلغائها (تبقى
     المقروءية للسجل).
   - لا يمكن الوصول إلى محادثة إلا برقم تذكرتها: الطالب عبر رابطه الخاص،
     والموظف عبر زر «محادثة» في صف كل تذكرة في اللوحة. لا يوجد فهرس
     للمحادثات ولا وصول متقاطع بين التذاكر، وملفات المحادثة تُخدم من
     مجلد التذكرة نفسها بأسماء عشوائية غير قابلة للتخمين.
   - الإرفاق: أي نوع ملف حتى 8MB (قابل للضبط عبر `MAX_UPLOAD_MB`)،
     والصور تُعرض داخل المحادثة مباشرة.

## متطلبات التشغيل

- Python 3.10 أو أحدث (اختُبر على 3.12).
- التبعيات في `requirements.txt` (Flask + Gunicorn).
- (اختياري) Docker + Docker Compose.
- (اختياري، لفحص الواجهة بالمتصفح) Playwright.

## تثبيت التبعيات

```bash
cd CrowdCloud_Chat
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
# للاختبارات:
pip install -r requirements-dev.txt
```

## أمر تشغيل المشروع

```bash
python run.py
```

وضع الإنتاج (نفس إعداد `Dockerfile`):

```bash
gunicorn --workers 4 --threads 2 --bind 0.0.0.0:5000 --timeout 60 run:app
```

بديل Docker (مرفقات المحادثة تدوم مع قاعدة البيانات داخل الحجم `/data`):

```bash
docker compose up --build
```

## الوصول إلى النظام محليًا

- الصفحة الرئيسية: `http://127.0.0.1:5000/`
- لوحة الطابور: `http://127.0.0.1:5000/queue`
- لوحة الموظف: `http://127.0.0.1:5000/admin`
- متابعة تذكرة: `http://127.0.0.1:5000/ticket/<رقم-التذكرة>`
- محادثة تذكرة (طالب): `http://127.0.0.1:5000/chat/<رقم-التذكرة>`
- محادثة تذكرة (موظف): `http://127.0.0.1:5000/chat/<رقم-التذكرة>?staff=1`

قاعدة البيانات تُنشأ تلقائيًا عند أول تشغيل في `database/crowdcloud.db`،
وجدول الرسائل يُنشأ/يُرحَّل تلقائيًا (قواعد النسخة الأساسية القديمة تُحدَّث
بعمود الطلب وجدول الرسائل دون فقدان بيانات). مجلد المرفقات `uploads/`
يُنشأ تلقائيًا أيضًا.

## تشغيل الاختبارات

```bash
pip install -r requirements-dev.txt
python -m pytest tests/ -v          # 45 اختبارًا (منها 12 لمحادثة والطلب)
bash scripts/qa_smoke.sh            # فحص وظيفي شامل بوضع Gunicorn (23/23)
./scripts/demo_scenario.sh http://127.0.0.1:5000
```

نتائج الأداء المسجّلة للنسخة الأساسية موجودة في `benchmarks/results/`
وتوثيقها في `VERIFICATION.md` (الطبقة الأساسية لم تتغير جوهريًا في هذه
النسخة؛ ميزات المحادثة مغطاة باختبارات pytest أعلاه).

## الإعدادات الضرورية

لا إعداد إلزامي؛ متغيرات البيئة الاختيارية:

| المتغير | الافتراضي | الوظيفة |
|---|---|---|
| `PORT` | `5000` | منفذ الخادم (`python run.py`) |
| `CROWDCLOUD_DB` | `database/crowdcloud.db` | مسار SQLite |
| `CROWDCLOUD_UPLOADS` | `uploads/` | مجلد مرفقات المحادثة (في Docker: `/data/uploads`) |
| `MAX_UPLOAD_MB` | `8` | الحد الأقصى لحجم الملف الواحد |
| `BUSY_THRESHOLD` | `8` | منتظرون للتحول إلى BUSY |
| `HIGH_THRESHOLD` | `16` | منتظرون للتحول إلى HIGH LOAD |
| `AUTO_SERVE` | `0` | محاكي الموظف الخلفي |
| `SECRET_KEY` | قيمة تطوير | عيّن قيمتك في أي نشر حقيقي |

ملاحظات نشر حقيقية فقط:

- عيّن `SECRET_KEY` بقيمة خاصة بك.
- `/api/demo/reset` تصفّر التذاكر والرسائل — احذفها أو احمِها قبل النشر العام.
- التحكم بجهة الإرسال (طالب/موظف) يتبع نموذج النموذج الأولي نفسه (لوحة
  الموظف مفتوحة بلا تسجيل دخول كما في النسخة الأساسية) — إن أردت توثيقًا
  صارمًا للموظفين فأضف تسجيل دخول قبل النشر الحقيقي.
